# Тест кейсове — Advanced Node & Express

Легенда: **P** = Priority (P1 критичен, P2 висок, P3 среден)

## Регистрация (`POST /register`)

| ID | Стъпки | Очакван резултат | P |
|---|---|---|---|
| TC-01 | Регистрирай нов потребител с уникален username/password | Потребителят се създава, пренасочва се към `/profile` | P1 |
| TC-02 | Регистрирай с вече съществуващ username | Заявката се пренасочва към `/`, не се създава дубликат в базата | P1 |
| TC-03 | Регистрирай с празен username или password | Определи и документирай очакваното поведение (валидация липсва в текущия код —flag за подобрение) | P2 |
| TC-04 | Регистрирай с username, съдържащ HTML/script tag | Стойността не се изпълнява като код при рендиране на `/profile` (XSS проверка) | P1 |

## Логин (`POST /login`)

| ID | Стъпки | Очакван резултат | P |
|---|---|---|---|
| TC-05 | Логни се с валидни креденшъли | Пренасочване към `/profile`, потребителското име се показва коректно | P1 |
| TC-06 | Логни се с грешна парола | Пренасочване обратно към `/` (failureRedirect) | P1 |
| TC-07 | Логни се с несъществуващ username | Пренасочване обратно към `/`, без изтичане на информация дали username съществува | P1 |
| TC-08 | Провери дали паролата се съхранява/сравнява в plain text | Документирай риска — препоръчай bcrypt hashing (dependency вече е наличен в `package.json`) | P1 |

## Профил (`GET /profile`)

| ID | Стъпки | Очакван резултат | P |
|---|---|---|---|
| TC-09 | Достъп до `/profile` без активна сесия | Пренасочване към `/` (ensureAuthenticated блокира достъпа) | P1 |
| TC-10 | Достъп до `/profile` с активна сесия | Показва се коректното потребителско име | P1 |
| TC-11 | Провери persist на сесията между отделни заявки (refresh) | Потребителят остава логнат до logout или изтичане на cookie | P1 |

## Изход (`GET /logout`)

| ID | Стъпки | Очакван резултат | P |
|---|---|---|---|
| TC-12 | Логни се, после кликни logout | Сесията се прекратява, пренасочва към `/` | P1 |
| TC-13 | След logout, опитай директен достъп до `/profile` | Пренасочва към `/`, а не показва кеширано съдържание | P1 |

## Обработка на грешки

| ID | Стъпки | Очакван резултат | P |
|---|---|---|---|
| TC-14 | Симулирай недостъпна MongoDB връзка | Показва се fallback error страница ("Unable to connect to database"), сървърът не крашва | P1 |
| TC-15 | Достъп до несъществуващ маршрут | Връща се `404 Not Found` (plain text) | P2 |

## Security / Session

| ID | Стъпки | Очакван резултат | P |
|---|---|---|---|
| TC-16 | Провери session cookie флаговете (`secure`, `httpOnly`) | Документирай дали `secure: false` е приемливо за production среда (HTTPS) | P2 |
| TC-17 | Опитай session fixation (използвай стар session ID след logout) | Старият session ID вече не дава достъп | P1 |
